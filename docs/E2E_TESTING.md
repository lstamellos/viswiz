# VisWiz browser E2E testing

VisWiz uses Playwright to exercise critical WordPress admin and public-browser workflows against a real WordPress + MySQL installation in GitHub Actions.

## Upstream references

- Playwright continuous integration: https://playwright.dev/docs/ci
- Playwright web server configuration: https://playwright.dev/docs/test-webserver
- WordPress Developer Blog — Getting started writing WordPress E2E Tests with Playwright: https://developer.wordpress.org/news/2026/05/getting-started-writing-wordpress-e2e-tests-with-playwright/
- WordPress `@wordpress/e2e-tests` reference: https://developer.wordpress.org/block-editor/reference-guides/packages/packages-e2e-tests/

The WordPress guidance recommends `wp-env` as a convenient local environment but explicitly does not require it. VisWiz reuses the same clean WordPress/MySQL setup pattern already used by its integration smoke job, then serves that installation over HTTP and drives it with Chromium. This avoids maintaining two independent WordPress test-environment definitions.

## CI contract

The `Chromium browser E2E` job:

1. creates a clean WordPress installation and activates the checked-out VisWiz plugin;
2. seeds deterministic row and graph datasets plus a published visualization/page;
3. starts WordPress through the PHP development server with a router that forwards non-file requests to `index.php`;
4. runs Playwright with one worker in CI for reproducibility;
5. retains traces, screenshots and video on failure and uploads the Playwright HTML report.

The fixture is generated by `tests/e2e/seed.php` and written to `VISWIZ_E2E_FIXTURE` so browser tests do not depend on hard-coded database IDs.

## Current acceptance coverage

The browser suite covers:

- row create/edit/delete;
- graph node create/edit/delete;
- graph relation create/delete;
- live graph preview updates after admin mutations;
- native dialog Enter/Escape paths and focus return;
- graph search and clear;
- node-type select filters and clear-all;
- type/subtype facet interaction;
- node modal rendering and sanitized rich description output;
- property views;
- related-node navigation while search hides the destination node;
- 1-hop/2-hop connection focus;
- relation-type-aware connection focus;
- zoom/reset and pointer pan path;
- fullscreen enter/exit when the browser exposes the Fullscreen API;
- multiple visualizations on one page;
- dynamically inserted visualization containers.

The suite intentionally targets critical workflows rather than DOM implementation details. Source/architecture tests remain appropriate for deterministic invariants; browser tests should prove behavior visible to an editor or visitor.

## Local execution

With a WordPress test installation available at `http://127.0.0.1:8889`, seed it with:

```bash
export VISWIZ_E2E_FIXTURE=/tmp/viswiz-e2e-fixture.json
wp eval-file tests/e2e/seed.php --path=/path/to/wordpress
```

Install Playwright and Chromium, then run:

```bash
npm install
npx playwright install --with-deps chromium
VISWIZ_E2E_BASE_URL=http://127.0.0.1:8889 npm run test:e2e
```

The CI workflow is the canonical reproducible environment if a local WordPress setup differs.
